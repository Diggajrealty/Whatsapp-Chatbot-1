Handing a lead to Kaira

Kaira is the WhatsApp assistant that greets your leads, answers questions about the project from the knowledge base, and books site visits. Luna posts the lead; Kaira opens the chat within seconds.

Base URL
https://kaira-whatsapp-production.up.railway.app
Auth header
x-api-key: <CRM_API_KEY>
Content type
application/json

The same key authenticates the site-visit callback Kaira sends back to Luna. A missing or wrong key returns 401 {"error":"invalid api key"}.

What changed

One number takes every lead

Kaira used to run a separate WhatsApp bot per builder — Sobha, Brigade, Godrej, Nambiar, Abhee — and the lead went to whichever one matched. You no longer have to know, or check, which builder bot is linked.

Every lead goes to the single main number. Kaira still introduces herself as the lead's own builder, taken from the property and builder you send — not from which number serves the chat.

So: stop sending botId. Routing is our problem now.

Sending a lead

POST /api/lead

This is the endpoint to use. It opens the WhatsApp chat and sends the first message immediately.

POST /api/lead
x-api-key: <CRM_API_KEY>
Content-Type: application/json

{
  "phone":    "9886000000",
  "property": "Abhee New Dimension",
  "builder":  "Abhee Developers",
  "name":     "Tanishq Sharma",
  "notes":    "Enquired via Housing.com, budget 1.4Cr, wants 3BHK"
}
FieldRequiredNotes
phone Yes Any format. 9886000000, +91 98860 00000, 09886000000 and 0091-98860-00000 all work. Bare 10-digit numbers are assumed Indian (+91).
property Strongly recommended The project enquired about, e.g. "Sobha Neopolis". Free text — matched case-insensitively against ~250 projects, and the spelling is corrected ("new dimension" → "Abhee New Dimension").
builder Optional e.g. "Godrej Properties". Used when property is missing or unmatched.
name Optional Only the first name is used, in the greeting.
notes Optional Free text. Given to the AI as context and searched for a project name when property is null.
botId Don't send Legacy override to force one specific bot. Leave it out.

About property: null

A lot of payloads arrive with "property": null and the project sitting in notes — "new property launch dsr villas". Kaira reads notes as a fallback, so those still work. But the greeting is much better when property is filled in, because Kaira can name the project and skip the "which project?" question.

If neither field names a project, the lead is still greeted and simply asked which project they mean. Nothing is dropped.

What comes back

StatusBodyWhat to do
200 {"ok":true,"botId":"all","whatsappId":"919886000000@c.us","sent":"Hi Tanishq! …"} Done. sent is the exact message the lead received — worth storing on the lead record.
400 {"error":"phone is required"} Fix the payload. Don't retry as-is.
401 {"error":"invalid api key"} Wrong or missing x-api-key.
404 {"error":"number is not on WhatsApp","phone":"919886000000"} Genuinely not a WhatsApp user. Don't retry — flag for a phone call.
503 {"error":"bot is reconnecting — retry shortly","botId":"all"} Transient. Retry with backoff, below.
500 {"error":"lookup failed: …"} Unexpected. Log the body, retry once, then tell us.

Retries — please implement this

A 503 means the WhatsApp session is mid-reconnect. It recovers by itself, usually within a minute. Queue the lead and retry on this schedule, then mark it failed for a human:

  • 60s
  • 2m
  • 5m
  • 10m
  • 20m
  • human

Every request is safe to retry. A lead sent twice just means the person gets greeted twice, which is far better than a dropped enquiry. Kaira answers within about 20 seconds, timing out cleanly rather than hanging, so a 30-second client timeout is enough.

Plain-English intake

POST /api/instruct

For when an agent types a sentence instead of a structured lead. Prefer /api/lead for anything automated.

{ "text": "Kaira, talk to 9886000000 about Abhee New Dimension" }

The phone is taken from the longest digit run in the sentence, and a phone field passed alongside text overrides it. The project must be named, or you get 400 {"error":"could not work out which project — mention it by name"}. Same codes as /api/lead, plus a parsed object showing what was understood — show that back to the agent so they can spot a misread.

Site visits come back to you

When a lead confirms a site visit in WhatsApp, Kaira POSTs to the URL configured as CRM_WEBHOOK_URL — currently https://luna-crm-api.vercel.app/kaira/site-visit — with the same x-api-key header.

{
  "phone":   "919886000000",
  "at":      "2026-09-20T11:00:00+05:30",
  "project": "Abhee New Dimension",
  "notes":   "Booked over WhatsApp with Kaira. Lead's words: \"sunday 11am works\""
}
FieldWhat it is
phoneDigits only, with country code. Match it against your lead records the way you'd match any normalized number.
atAlways an absolute ISO-8601 instant with an offset (+05:30) — never a bare local time, so there is no timezone guessing on your side. If the AI produces an unusable date, we log it and don't call you; those get booked by hand.
projectBest-effort canonical project name, or the builder, or omitted.
notesIncludes the lead's own words that confirmed the slot.

Respond 2xx if you booked it. Use 422 when you understood the request but couldn't place it — unknown lead, no matching project — so those are logged distinctly and someone chases them.

The call is fire-and-forget with a 10-second timeout. If your API is down, the lead's WhatsApp conversation carries on normally, but the booking exists only in our log. A 5xx from you means a visit that needs manual entry.

Two lookups worth using

GET /api/projects

Every builder and project as Kaira knows them. Use it to normalize property before sending — it removes almost all "which project did they mean?" ambiguity. Cache it; it changes rarely.

{
  "builders": [
    { "builder": "Sobha Limited", "botId": "sobha", "projects": ["Sobha Neopolis", "…"] }
  ]
}
GET /api/bots

Is the service live? status is one of stopped, starting, qr (needs a QR scan — a human has to act), authenticated, ready, or degraded (wedged, recycling itself).

[{ "id": "all", "builder": "All Builders", "status": "ready" }]

You don't need to poll this before sending a lead — just send it and handle the 503. It's there for dashboards and alerting.

Checklist for the Luna side

  1. POST /api/lead with x-api-key. Never send botId.
  2. Fill property from the CRM whenever it exists; put everything else in notes.
  3. Store the returned sent text and whatsappId on the lead.
  4. Treat 503 as retryable with backoff; 400 and 404 as terminal.
  5. Accept the site-visit webhook. Return 2xx on success, 422 when you can't place it.
  6. Normalize project names against GET /api/projects.
